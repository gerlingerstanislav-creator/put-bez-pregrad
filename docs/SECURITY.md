# Безопасность и подготовка к публикации исходного кода

## Данные, которые не должны быть в Git

- FTP/FTPS/SFTP логин и пароль.
- Действующий пароль, bootstrap bcrypt-хеш и приватный путь админки.
- SMTP пароль и сохранённые серверные настройки.
- Содержимое заявок и персональные данные пассажиров.
- `.env` с секретами, `.pbp-private/` (runtime data), `vendor/`, `dist/`.

GitHub Secrets используются только для значений, необходимых процессу публикации; **секреты не нужно записывать в файлы `dist/`**. Приватный путь админки является исключением лишь в составе имени каталога релиза, а не значением JS-константы.

## Что намеренно публично

Телефоны, контактная почта, текст сайта, видимые иллюстрации, логика формы, правила проверки данных и названия SMTP-провайдеров. Код публичного API должен оставаться безопасным при полном раскрытии.

## Перед переключением репозитория в public

1. Убедиться, что новый root-коммит не имеет родителей, а видимые ветки не ссылаются на старую историю.
2. Просмотреть PR, старые GitHub Actions, кэш и возможные реплики: очистка ветки не гарантирует полного удаления коммитов из инфраструктуры GitHub.
3. Проверить отсутствие секретов автоматическим сканером и ручным аудитом всех текстовых файлов.
4. Сменить любой пароль, который мог попасть в историю или чат; проверить FTP и административные сессии.
5. Убедиться, что CI работает; выполнить PHP и браузерные тесты, не затрагивая production.
6. Проверить HTTPS, скрытую админку, отсутствие старых маршрутов и доставку SMTP письма.
7. Только после отдельного согласования владельца делать репозиторий публичным и запускать деплой.

## Ограничения текущей инфраструктуры

Настройки на Timeweb размещаются в `.pbp-private/` внутри существующего `public_html`, поскольку PHP не может писать снаружи. Защита комбинированная: Apache `.htaccess` закрывает путь, все файлы с содержимым — `*.php` с немедленным HTTP 404, включая ключ формы и счётчики. **Риск:** при ошибочной отдаче исходного PHP-кода вместо исполнения защита не гарантируется, поэтому проверка прямых HTTPS-запросов к `state.php` обязательна. FTP исторически используется без шифрования; отдельный минимально привилегированный пользователь обязателен. Даже при корректном HTTPS посетителей FTP остаётся отдельным каналом передачи секретов.

Уникальный URL панели уменьшает шум сканеров, **но не заменяет** пароль, ограничения попыток и защищённые сессии.

## Одноразовая смена пароля при релизе

Production workflow получает `PBP_ADMIN_PASSWORD_HASH` из GitHub Secrets для единственного HTTPS-запроса. Перед FTP-загрузкой создаётся короткоживущий PHP-обработчик под случайным именем; файл содержит только SHA-256 случайного одноразового токена и срок действия, **не пароль и не его хеш**. Обработчик инициализирует защищённый `state.php`, если его ещё нет, и обновляет только `password_hash` и поколение сессий. Существующие SMTP и контакты сохраняются. Второй проход FTP-синхронизации удаляет обработчик; срок его действия максимум 15 минут. При сбое предусмотрена попытка очистки. Результат нужно проверить по новому паролю через HTTPS.
