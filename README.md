# Путь без преград

Самостоятельный публичный одностраничный сайт перевозки людей на инвалидных колясках в Ульяновске и области. Исходная страница перенесена из [project-0](https://github.com/gerlingerstanislav-creator/project-0), зависимость от Laravel/Inertia удалена.

**Стек:** Vue 3, Vite, Tailwind CSS 4 + минимальный PHP 8.2 API. Публичный интерфейс и закрытая панель управления собираются в статические файлы, а PHP принимает заявки и сохраняет настройки.

## Локальная работа

Подробности для нового разработчика: [запуск и разработка](docs/DEVELOPMENT.md), [архитектура](docs/ARCHITECTURE.md), [безопасность и публикация](docs/SECURITY.md).

```bash
npm install
npm run dev
npm run check
npm run build
node scripts/check-dist.mjs
```


Иконка вкладки (`public/images/put-bez-pregrad/favicon.svg`) повторяет знак доступного транспорта в цветах сайта (графит, красный и бирюзовый) на прозрачном фоне, без квадратной подложки. Используется на сайте и в закрытой административной панели.

Логотип в шапке использует **тот же знак** `favicon.svg` рядом с текстом «Путь без преград». В тёмном подвале используется геометрически идентичный знак `brand-symbol-light.svg` (светлый вместо тёмного графитового контура) и тот же текст. Предыдущие полноценные логотипы `logo.svg` и `logo-light.svg` **сохранены без изменений** в каталоге `public/images/put-bez-pregrad/` для возможного возврата.

## Форма заявки и администрирование

- Форма **автоматически отправляет письмо** через SMTP (PHPMailer; Timeweb 465/SSL, Яндекс 587/STARTTLS). Перед отправкой действует honeypot, серверная валидация, лимит по IP/телефону и подписанный ограниченный по времени challenge формы (3–1800 секунд); заявка по-прежнему не сохраняется в базе. Кириллические домены ящиков нормализуются в Punycode на сервере (есть полифилл `intl`, если расширение не установлено). Админка сохраняет прежний пароль; тест SMTP показывает отдельный код ошибок авторизации/сети/TLS/адреса вместо одного сообщения. Для подтверждения доставки проверьте тестовое письмо в ящике.
- Админка доступна **только по длинному уникальному адресу**, задаваемому GitHub Secret `PBP_ADMIN_PATH` при сборке; публичных ссылок нет. `/admin/` и старые `/api/admin.php`, `/api/settings.php` отключены. Вход защищён паролем, CSRF-токеном и ограничением попыток; сессионная cookie имеет флаги `Secure`, `HttpOnly`, `SameSite=Strict` и действует только в приватном пути. SMTP и настройки по-прежнему редактируются без деплоя.
- Первоначальный хеш пароля **не содержится в исходниках**. После миграции конфигурация находится в `private/state.php` вне web-root; при первой публикации временный защищённый обработчик инициализирует состояние, если его ещё нет.
- Настройки и пароль хранятся в `private/state.php` **вне webroot**, а не в GitHub. Публичный сайт помещается в `web/`, `public_html` становится ссылкой на него. Сначала проверяется право PHP на запись в `private/`; обработчики админки публикуются отдельно в `private/admin-api/`.
- База данных не нужна. Для заявок используется SMTP-ящик Timeweb или Яндекс, реквизиты сохраняются только в `.pbp-private` вне сайта. Кнопка тестового письма работает после сохранения настроек. Не сохраняем заявки на сервере, используем валидацию и ограничение частоты.
- **HTTPS:** редирект HTTP → HTTPS учитывает штатный заголовок Timeweb `X-HTTPS: 1` после TLS-терминации; редирект может возвращаться с кодом 301 (на уровне провайдера) или 308 (на уровне Apache). Административный PHP API также проверяет HTTPS до запуска сессии. **Перед включением на Timeweb необходимо проверить действительный SSL-сертификат для рабочего домена и работу правил `.htaccess`**. Старые HTTP-сессии перестают подходить после переноса админки. FTP-публикация по-прежнему не шифруется.
- Для юридически корректной обработки персональных данных ещё требуется заполненная политика с реквизитами оператора. Пока на форме есть отдельное согласие, но оно не заменяет весь комплект документов.

Контактные номера автоматически приводятся к `+7 (999) 123-45-67` или `+7 (8422) 71-73-03`, поддерживаются ввод и вставка через `8`, `+7` и 10 цифр; email — нативная проверка, отсутствие автозаглавных букв и приведение домена к нижнему регистру при потере фокуса. Бургер в узкой шапке расположен слева от логотипа, меню накладывается поверх страницы.

Публичный API: `GET /api/public.php` (контакты и короткоживущий подписанный challenge), `POST /api/submit.php` (SMTP-заявка). Административный API находится только в скрытом каталоге панели и требует пароль/сессию. URL доступа сообщается владельцу отдельно.

## Развёртывание

`.github/workflows/deploy.yml` запускается **только вручную** через GitHub Actions и публикует `dist/` в `web/`, а `private-dist/admin-api/` — в `private/admin-api/` по SSH/rsync. При первом запуске выполняется [миграция с тестом PHP-доступа и откатом](docs/TIMEWEB_MIGRATION.md).

Composer устанавливает PHPMailer в CI, после чего в `dist/api/vendor` попадает только библиотека без SMTP-реквизитов. `private/state.php` в сборку не входит и при публикации не затирается.

GitHub Secrets для новой схемы: SSH-реквизиты и уже существующие секреты админки (см. [инструкцию по миграции](docs/TIMEWEB_MIGRATION.md)). Старые FTP-секреты не используются:

| Secret | Что задавать |
|---|---|
| `PBP_ADMIN_PATH` | Случайный путь закрытой панели |
| `PBP_ADMIN_PASSWORD_HASH` | BCrypt-хеш пароля администратора с фактором сложности не ниже 12 |
| `TIMEWEB_SSH_*` | SSH-хост, порт, пользователь, приватный ключ и проверенный known_hosts |
| `TIMEWEB_SITE_ROOT` | Абсолютный путь к родительской директории `public_html` |

Публикация выполняется по SSH, без старого FTP.

Сайт Timeweb: `bpreg.tw1.ru`. Домен `путь-без-преград73.рф` требует корректных DNS и действующего сертификата. **Не объединять эту ветку в `main`, пока HTTPS не проверен для действующего домена; иначе принудительный редирект может временно сделать сайт недоступным.**

Изображения автопарка демонстрационные, а не фотографии реальной машины.

Исходники: `src/App.vue` (лендинг), `src/Admin.vue` (админка), `src/composables/useTransportRequest.js` (заявка), `src/styles/` (стили страниц), `public/api` (PHP + антиспам), `src/components/` (иконки), `public/images/` (иллюстрации).

### Диагностика SMTP и адреса .рф

- `noreply@путь-без-преград73.рф` приводится к `noreply@xn----73-63depjfbu6gfocwq7n.xn--p1ai` до проверки PHP и SMTP-авторизации. В админке можно вводить кириллицу, она остаётся читаемой для администратора.
- Для конвертации используются `intl` или `symfony/polyfill-intl-idn` (устанавливается Composer CI); тесты запускаются в том числе через `php -n`, без расширения `intl`.
- При неуспешной отправке админка показывает только категорию: `SMTP_AUTH_FAILED`, `SMTP_TLS_FAILED`, `SMTP_CONNECTION_FAILED`, `SMTP_ADDRESS_REJECTED` и др.; пароли и SMTP-транскрипт не отображаются.
- Кнопка старого теста `PHP mail()` удалена, чтобы не путать два способа отправки.

- После ошибки `SMTP_CONNECTION_FAILED` на Timeweb 587/STARTTLS выбран альтернативный официально поддерживаемый вариант 465/SSL. Результат фактической отправки подтверждается только тестом из админки; успех CI сам по себе не означает доставку почты.

### Секретный адрес админки

В `production` укажите GitHub Secret `PBP_ADMIN_PATH` (20–80 букв/цифр/дефисов). Команда `npm run build` перемещает готовую панель и PHP-обработчики в этот каталог; в репозитории его имя не хранится. Без переменной локальная сборка использует тестовый путь `local-admin-preview-only`, **не предназначенный для публикации**. Не публикуйте собранную локально версию без секрета. `PBP_ADMIN_PASSWORD_HASH` используется в одноразовой HTTPS-миграции пароля во время согласованного деплоя; SMTP и контакты сохраняются. Хеш не сохраняется в загруженных файлах, временный PHP-обработчик удаляется после вызова (срок действия не более 15 минут).
