# Миграция Timeweb на изолированный webroot

## Структура

SITE_ROOT (родитель нынешнего public_html):

    public_html -> web/           # символьная ссылка
    web/                          # публичные HTML/CSS/JS/PHP
      <PBP_ADMIN_PATH>/           # публичный UI и PHP-шлюзы админки
    private/                      # за пределами webroot
      state.php                   # пароль администратора, SMTP и контакты
      form-challenge.key
      rate_*.php
      admin-api/                  # настоящие обработчики админки
    public_html.pbp-backup-.../   # резервная копия старого webroot

Интерфейс входа должен быть доступен браузеру; реальные обработчики и все конфиденциальные данные вынесены за webroot. Существующий URL сайта не меняется.

## Ограничения Timeweb

Timeweb поддерживает символьную ссылку public_html -> web, но при включённой изоляции доступ PHP к соседней private/ не гарантируется. Перед переключением короткоживущий PHP-пробник проверяет реальную запись в private/ по HTTPS через прежний сайт; при отрицательном результате старый public_html остаётся на месте. Не использовать chmod 777 и не помещать пароли в открытый webroot.

Документация:
- https://timeweb.com/ru/docs/virtualnyj-hosting/prilozheniya-i-frejmvorki/yii/
- https://timeweb.com/ru/docs/virtualnyj-hosting/rabota-s-sajtom/izolyaciya-sajtov/

## Новые GitHub Secrets для ручного деплоя

- TIMEWEB_SSH_HOST — SSH-хост аккаунта Timeweb.
- TIMEWEB_SSH_PORT — порт SSH, указанный в Timeweb (обязателен).
- TIMEWEB_SSH_USER — пользователь SSH с правом изменения сайта.
- TIMEWEB_SSH_PRIVATE_KEY — приватный ключ отдельного деплой-пользователя.
- TIMEWEB_SSH_KNOWN_HOSTS — проверенная запись SSH-хост-ключа, не результат непроверенного ssh-keyscan.
- TIMEWEB_SITE_ROOT — абсолютный путь к родительской директории существующего public_html, например /home/u/account/site (только пример).
- PBP_ADMIN_PATH и PBP_ADMIN_PASSWORD_HASH — действующие GitHub Secrets, без изменений.

Ключ и адрес админки не нужно отправлять в чат или сохранять в репозитории.

## Порядок

1. Создать вышеперечисленные Secrets в GitHub (при наличии production Environment — в нём).
2. Вручную запустить GitHub Actions: Deploy isolated webroot to Timeweb.
3. Workflow проверяет Node/PHP, HTTPS, SSH, формирует сборки dist/ (web) и private-dist/admin-api/ (backend).
4. Через SSH создаёт web/ и private/, без перезаписи переносит state.php и form-challenge.key из существующей .pbp-private/, если они есть.
5. Загружает файлы в web/ и private/admin-api/ через SSH/rsync, не меняя текущий public_html.
6. Через временный PHP-файл под случайным именем проверяет HTTP-доступ PHP к private/, сразу удаляет его.
7. Только после успешной проверки переименовывает старый public_html в резервную копию и создаёт символьную ссылку public_html -> web.
8. Проверяет публичный PHP API; при ошибке немедленно восстанавливает прежний каталог.
9. Выполняет одноразовую инициализацию/смену пароля администратора по HTTPS; существующие SMTP и контакты сохраняются.
10. Удаляет временный bootstrap, проверяет публичный API, приватный URL, старые URL и запрет доступа к /private/. При ошибке первой миграции пытается автоматически вернуть предыдущий webroot.
11. После успешного релиза резервная копия старого public_html сохраняется до ручной проверки и удаления.

Последующие деплои используют ту же директорию web/ и отдельный каталог PHP private/admin-api/. Конфигурация private/state.php не удаляется и не перезаписывается.

## Если миграция остановилась

Если PHP-пробник возвращает ошибку записи — публичный сайт не переключался. Проверьте, что TIMEWEB_SITE_ROOT обозначает корень нужного сайта и что включённая в Timeweb изоляция допускает доступ к private/ внутри него. На общем хостинге нельзя произвольно настраивать Nginx.

Если SSH недоступен, нельзя безопасно заменить public_html на символьную ссылку существующими FTP-реквизитами. Не запускайте старый FTP-деплой с новой PHP-сборкой.

На чистой установке после входа необходимо вручную настроить SMTP-пароль и отправить тестовое письмо: CI не может подтвердить доставку сообщения без реальных SMTP-реквизитов.
