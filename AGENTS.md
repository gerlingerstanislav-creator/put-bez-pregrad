# Инструкции по сопровождению

- Это независимый Vue + Vite сайт с минимальным PHP 8.2 API без Laravel и базы данных.
- Главный источник пользовательского интерфейса — `src/App.vue`, компоненты — `src/components/`, фотографии и логотипы — `public/images/`.
- Проверяй сайт на desktop/mobile и работу ссылок tel:, mailto: и MAX.
- Перед изменениями `main` проверь текущий HEAD и файлы. Перед push: `npm run check && npm run build && node scripts/check-dist.mjs`.
- Обновляй README при изменении поведения, инфраструктуры или деплоя.
- Не добавляй ключи, пароли, токены или production-секреты в исходники и логи.
- Публикация через FTP порт 21 (обычный FTP без шифрования — ограничение виртуального хостинга). Для CI/CD использовать только отдельного FTP-пользователя с доступом к каталогу сайта; позже при появлении SSH рассмотреть безопасный SFTP. Публиковать только dist и не очищать хостинг целиком.
- Форма заявки отправляет через PHPMailer SMTP/STARTTLS на email из настроек (для настройки нужны отдельные SMTP-реквизиты в админке); текст заявки не хранится на сервере. Контакты и пароль редактируются только по приватному URL панели, состояние хранится в каталоге .pbp-private/state.php вне public_html и никогда не отслеживается Git. Не переноси конфигурацию и секреты внутрь public_html: Timeweb отдаёт статические файлы из директорий несмотря на локальный .htaccess. Проверяй PHP синтаксис и изоляцию приватных данных; пароль всегда хешировать password_hash(). При включении HTTPS защищать cookie флагом Secure и сбрасывать старые HTTP-сессии.

- При изменении полей телефонов поддерживай общий модуль `src/utils/contactInput.js` и тесты `tests/contact-input.test.mjs`; не допускай неполные телефонные номера к серверу.
- Для отправки почты используй PHPMailer из `mail-php/composer.json`, проверяй наличие `dist/api/vendor/autoload.php` и не выводи SMTP-пароль ни в логах, ни в API.
- В мобильном меню не меняй высоту шапки при открытии: меню поверх контента и слева от логотипа кнопка.


- SMTP IDN: для адресов `.рф` канонизируй домены Punycode до `filter_var`, `setFrom` и SMTP `Username`; кириллица в локальной части email не поддерживается. Важны `symfony/polyfill-intl-idn >=1.38.1` и PHP-тесты с `php -n` без `intl`. Не возвращай SMTP-транскрипт, адреса и секреты в ответы для посетителя.

- Почтовый транспорт Timeweb: 465/SSL, Яндекс: 587/STARTTLS. Не объявляй отправку работающей только по успешной сборке, проверяй тестовым письмом из админки.

## Защита административного доступа и формы

- Приватный путь панели не указывай в публичной навигации, sitemap, robots.txt или README. Не возвращай его через публичный PHP API.
- Старые `/admin/`, `/api/admin.php` и `/api/settings.php` должны оставаться недействующими.
- Настройки SMTP и их хранилище `.pbp-private` не переносить. Сохранить существующую отправку через PHPMailer.
- Защита формы: honeypot, подписанный challenge со сроком жизни, ограничение количества запросов и валидация полей на сервере.
- Для HTTPS использовать перенаправление 308 (с сохранением метода POST), а для административных cookie `Secure`, `HttpOnly`, `SameSite=Strict` и приватный Path.
- **Перед развёртыванием HTTPS-редиректов проверить сертификат текущего домена на Timeweb.** Публиковать в main только после отчёта и согласования владельца.

- Запрещено коммитить приватное имя каталога панели: сборка берёт `PBP_ADMIN_PATH` из production GitHub Secret. Локальное имя только для тестов, без деплоя.
- Bootstrap-hash администратора не должен быть в исходниках или в `dist/`. На работающем сервере хеш хранится в `.pbp-private/state.php` и не перезаписывается релизом.

- Production-деплой запускается только вручную после явного согласования владельца; push в main не должен публиковать сайт автоматически, пока не завершено согласование.
