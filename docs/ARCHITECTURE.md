# Архитектура «Путь без преград»

## Что это за проект

Это небольшой независимый сайт перевозок, а не часть Laravel-проекта. Пользовательский сайт и панель управления — два отдельных Vue 3 entrypoint. Vite собирает JS/CSS в `dist/`; PHP 8.2 на Timeweb обрабатывает JSON API, хранит настройки и отправляет письма через PHPMailer. База данных не используется.

## Уровни и ответственность

| Слой | Каталог | За что отвечает |
|---|---|---|
| Страницы | `src/App.vue`, `src/Admin.vue` | Композиция разделов, состояние авторизации и административные операции |
| Блоки лендинга | `src/components/landing/` | Шапка, первый экран, преимущества, направления, автопарк, форма, футер |
| Блоки админки | `src/components/admin/` | Вход, контакты, SMTP, смена пароля |
| Поведение | `src/composables/` | Загрузка контактов, отправка формы и отображение её состояния |
| Форматирование | `src/utils/` | Номера телефонов, email, HTTP→HTTPS fallback |
| CSS | `src/styles/` | Стили лендинга и админки; `src/styles.css` содержит общие стили |
| Публичный PHP API | `public/api/` | Отправка заявок, публикация безопасных контактов, антиспам, SMTP |
| Административный PHP | `server/admin-api/` | Аутентификация, настройка контактов и SMTP; попадает только в приватный путь сборки |
| Сборка | `vite.config.js`, `scripts/` | Сборка двух entrypoint и упаковка админки |
| CI/CD | `.github/workflows/` | Отдельно проверки и ручной релиз на Timeweb |

## Как проходят запросы

- Главная страница: `src/main.js` → `App.vue` → компоненты `src/components/landing/`.
- Контакты: `useSiteContacts()` → `GET /api/public.php`. При сбое API остаются безопасные публичные значения по умолчанию.
- Заявка: `PricingRequestSection.vue` → `useTransportRequest()` → `POST /api/submit.php` → серверная валидация, honeypot и challenge → PHPMailer/SMTP. Пароль SMTP не передаётся в браузер.
- Админка: `src/admin.js` → `Admin.vue` → компоненты `src/components/admin/`. Её API упаковывается рядом с приватным entrypoint; логин и операции защищены сессией и CSRF.
- Серверное состояние: `.pbp-private/state.php` внутри `public_html`, закрыт от HTTP через `.htaccess` и PHP guard; деплой не должен его переписывать.

## Основные правила модификации

1. Меняй отдельный компонент нужного раздела, а не наращивай `App.vue`.
2. Сетевые запросы и обработку состояния размещай в composable/API-модуле, не в шаблоне.
3. PHP всегда повторно проверяет входные данные: браузерная валидация лишь помогает пользователю.
4. SMTP, cookie и пароль администратора не выводятся в клиентский JavaScript или репозиторий.
5. Сохраняй существующие классы CSS и структуру DOM, если не изменяешь дизайн сознательно.
6. Для новых функций добавляй тесты, документацию и выполняй сборку до релиза.
7. Работающий Timeweb не обновляется автоматически по push. Деплой — отдельное согласованное действие.

## Управление доступом

Приватный путь админки приходит **только** из секрета `PBP_ADMIN_PATH` при ручном деплое. Исходный шаблон `admin/index.html` доступен в git разработчику; упаковщик переносит его в закрытый URL и заменяет `/admin/` страницей 404. Секрет не должен упоминаться в README, коде или скриншотах. Незнание пути не заменяет пароль, rate-limit и HTTPS.

Секрет `PBP_ADMIN_PASSWORD_HASH` не входит в статическую сборку; действующий хеш находится только на сервере, в приватном состоянии. Если состояние исчезло, админка должна закрываться, а не выдавать дефолтный пароль.

## Сборка и релиз

`npm run build` запускает Vite, затем `scripts/finalize-build.mjs` перемещает готовую админку и PHP-обработчики в путь `PBP_ADMIN_PATH`. Без переменной используется фиксированный **локальный тестовый путь**. Такие артефакты нельзя отправлять на рабочий сайт. `scripts/check-dist.mjs` проверяет структуру собранной версии.

Поскольку сервер на Timeweb обслуживает статические страницы самостоятельно, `.htaccess` может не распространяться на весь трафик в конфигурациях с Nginx. PHP дополнительно принуждает HTTPS, браузерный fallback покрывает статические Vue-страницы. Полный серверный HTTP→HTTPS redirect проверяется отдельно перед релизом.
